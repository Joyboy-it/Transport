# โครงหน้าจอแบบ ERP และชุดสีใหม่

วันที่ 15 พฤศจิกายน 2026 · สถานะ: รอเจ้าของงานอนุมัติ

ภาพต้นแบบที่เจ้าของงานเลือกแล้ว: [assets/2026-11-15-erp-shell-mockup.html](assets/2026-11-15-erp-shell-mockup.html) เปิดในเบราว์เซอร์ได้โดยตรง โทนที่ใช้คือ "1 น้ำเงินองค์กร" (`data-theme="navy"`) อีกสองโทนในไฟล์ไม่ใช้ ค่าสี ขนาด และระยะในเอกสารนี้ตรงกับโทนนั้น ถ้าเอกสารกับภาพต้นแบบขัดกัน ให้ถือเอกสาร

## ที่มา

โปรแกรมตอนนี้คือระบบจ้างรถขนส่งระบบเดียว ชื่อระบบและเมนูทั้งหมดฝังอยู่ในโครงหน้าจอ เจ้าของงานจะเพิ่มระบบอื่นเข้ามาในโปรแกรมเดียวกันภายหลัง เพื่อไม่ต้องทำแอปแยกและไม่ให้คนต้องเข้าหลายที่ พนักงานคนเดียวกันจะใช้หลายระบบ

เจ้าของงานยังไม่พอใจหน้าตาปัจจุบัน โดยเฉพาะสี และต้องการให้หน้าจอแบ่งเป็นสัดส่วนชัดเจน หน้าตาถูกปรับมาแล้วสามรอบโดยไม่ได้ให้เลือกจากภาพ รอบนี้จึงเลือกจากภาพต้นแบบก่อน

เงื่อนไขที่เจ้าของงานกำหนด: ห้ามกระทบกฎการทำงานของระบบ

## เป้าหมาย

1. โครงหน้าจอแบ่งเป็นสี่ส่วนคงที่: แถบระบบ เมนูของระบบ แถบบน และพื้นที่เนื้อหา
2. เพิ่มระบบใหม่ได้โดยลงทะเบียนระบบหนึ่งรายการและสร้างโฟลเดอร์หน้าของระบบนั้น โดยไม่แก้โครงหน้าจอ
3. ระบบจ้างรถขนส่งกลายเป็นระบบแรกในโครงนี้ ทุกหน้า ทุกฟอร์ม และทุกปุ่มทำงานเหมือนเดิม
4. สีมาจากชุดสีกลางชุดเดียว สีหนึ่งสีมีความหมายเดียวทั้งโปรแกรม
5. หน้าตาตรงกับภาพต้นแบบโทน 1

## ไม่ทำในงานนี้

- ไม่สร้างระบบใหม่ ระบบสีจางในภาพต้นแบบ (จัดซื้อ คลัง บัญชี) เป็นแค่ตัวอย่างตำแหน่ง ห้ามใส่ในโปรแกรมจริง
- ไม่เปลี่ยนเนื้อในของหน้า: ลำดับช่อง คอลัมน์ตาราง ข้อความ ขั้นตอน และเนื้อหาในหน้าต่างย่อย คงเดิม เปลี่ยนเฉพาะสีและส่วนประกอบกลางที่หน้านั้นใช้
- ไม่เปลี่ยนบทบาทและสิทธิ์
- ไม่ทำแดชบอร์ด กราฟ ค้นหารวม การแจ้งเตือน
- ไม่ทำโหมดมืด บล็อก `.dark` ใน `globals.css` ไม่มีอะไรเปิดใช้อยู่ ให้คงไว้ตามเดิม ไม่ต้องเพิ่มค่าสีใหม่ให้
- ไม่เปลี่ยนผลการพิมพ์
- ไม่เพิ่มแพ็กเกจ และไม่โหลดฟอนต์จากอินเทอร์เน็ต เครื่องใช้งานอยู่ใน LAN
- ไม่ทำให้ข้อมูลหลักใช้ร่วมกันข้ามระบบ

## สิ่งที่ถือว่าล้มเหลวแม้โปรแกรมทำงานได้

- ค่าที่บันทึก ผลคำนวณ สถานะใบงาน หรือสิทธิ์ ต่างจากเดิมในกรณีใดก็ตาม
- หน้าหรือปุ่มที่เคยมีหายไป
- ลิงก์เดิมที่ผู้ใช้เก็บไว้เปิดไม่ได้
- งานประจำวันต้องคลิกมากกว่าเดิม: จากหน้าใดก็ตามในระบบขนส่ง ต้องไปถึงใบงานและคิวงานทั้งสามได้ในคลิกเดียวเหมือนตอนนี้
- หลังบันทึกแล้วหน้าจอแสดงข้อมูลเก่า
- มีข้อมูลทดสอบค้างอยู่ในฐานข้อมูลจริง

## ข้อจำกัด

- Next.js 16.4.5 แบบ App Router, React 19, Tailwind 4, shadcn บน Base UI, lucide-react เวอร์ชัน Next นี้ต่างจากที่คุ้นเคย ให้อ่านคู่มือใน `node_modules/next/dist/docs/` ก่อนเขียนโค้ด ตาม `AGENTS.md`
- หน้าจอเป็นภาษาไทย ชื่อในโค้ดเป็นภาษาอังกฤษ ศัพท์ตาม `GLOSSARY.md`
- เซิร์ฟเวอร์ใช้งานจริงรันอยู่ที่พอร์ต 3000 จากผล `build` ด้วยงาน `TransportServer` ของ Windows เซิร์ฟเวอร์ระหว่างพัฒนาต้องใช้พอร์ตอื่น
- ทั้งโปรเจกต์ยังไม่เคยถูกบันทึกใน git นอกจากไฟล์ตั้งต้นของ Next ก่อนแก้ไฟล์ใดต้องบันทึกสถานะปัจจุบันเป็นจุดย้อนกลับ และต้องได้รับอนุญาตจากเจ้าของงานก่อนบันทึก
- ฐานข้อมูลที่ `.env` ชี้อยู่คือฐานจริง การทดสอบที่มีการบันทึกต้องทำกับฐานแยก
- ไม่มีชุดทดสอบหน้าจออัตโนมัติ ชุดทดสอบที่มีครอบคลุมเฉพาะ `src/domain`, `src/lib` และ `src/server`

## การออกแบบ

### 1. โครงหน้าจอ

```
| แถบระบบ | เมนูของระบบ     | แถบบน: ปุ่มย่อเมนู · ตำแหน่งหน้า        ผู้ใช้ · ออกจากระบบ |
| 76px    | 232px          |------------------------------------------------------|
|         |                | พื้นที่เนื้อหา                                          |
```

**แถบระบบ** กว้าง 76px สูงเต็มจอ พื้นน้ำเงินเข้ม
- บนสุดคือสัญลักษณ์ของโปรแกรม
- ถัดลงมาคือ "หน้าแรก" แล้วตามด้วยระบบตามลำดับในทะเบียนระบบ
- ระบบ "ผู้ดูแลระบบ" อยู่ล่างสุดเสมอ
- แต่ละรายการมีไอคอนและชื่อสั้นใต้ไอคอน ขนาดตัวอักษร 12px พื้นที่กดอย่างน้อย 56px
- รายการของระบบที่กำลังเปิดอยู่มีพื้นสีหลัก
- แสดงเฉพาะระบบที่ผู้ใช้มีสิทธิ์เห็น

**เมนูของระบบ** กว้าง 232px พื้นขาว มีเส้นขอบขวา
- หัวเมนูแสดงคำว่า "ระบบ" และชื่อเต็มของระบบ
- รายการเมนูแบ่งกลุ่มพร้อมหัวกลุ่ม รายการสูง 38px
- รายการที่เปิดอยู่มีพื้นฟ้าอ่อน ตัวอักษรสีหลัก และแถบสีหลักกว้าง 3px ที่ขอบซ้าย
- ตัวเลขจำนวนงานอยู่ชิดขวาของรายการ เลขศูนย์แสดงเป็นสีเทา
- หน้าแรกไม่มีเมนูของระบบ เนื้อหาใช้พื้นที่ส่วนนี้ด้วย

**แถบบน** สูง 54px พื้นขาว มีเส้นขอบล่าง ติดอยู่บนสุดเมื่อเลื่อนหน้า
- ซ้าย: ปุ่มย่อเมนู และตำแหน่งหน้าในรูป "ชื่อระบบ › ชื่อรายการเมนูที่เปิดอยู่"
- ขวา: ชื่อที่แสดงของผู้ใช้ บรรทัดรองเป็น "ชื่อผู้ใช้ · ชื่อบทบาท" และปุ่มออกจากระบบซึ่งเรียก `logoutAction` ตัวเดิม
- บล็อกผู้ใช้และปุ่มออกจากระบบย้ายมาจากท้ายเมนูเดิม

**พื้นที่เนื้อหา** พื้นเทาอ่อน เนื้อหาอยู่ในการ์ดขาว ระยะขอบ 24px บนจอกว้าง และ 16px บนมือถือ หัวหน้า (`PageHeader`) ยังอยู่ในเนื้อหาเหมือนเดิม

**ย่อเมนู** ปุ่มในแถบบนซ่อนและแสดงเมนูของระบบบนจอกว้าง เพื่อให้ตารางกว้างขึ้น จำสถานะไว้ในเบราว์เซอร์เครื่องนั้น ค่าเริ่มต้นคือแสดง

**จอแคบกว่า 768px** แถบระบบและเมนูของระบบซ่อน ปุ่มเมนูในแถบบนเปิดแผงเลื่อนจากซ้ายที่มีทั้งรายการระบบและเมนูของระบบที่เปิดอยู่ แผงปิดเมื่อแตะลิงก์ แตะพื้นหลัง หรือกด Esc

**การพิมพ์** แถบระบบ เมนู และแถบบนไม่พิมพ์ เหมือนที่เมนูเดิมไม่พิมพ์

### 2. ทะเบียนระบบ

มีที่เดียวที่บอกว่าโปรแกรมมีระบบอะไรบ้าง แถบระบบ เมนู ตำแหน่งหน้า และหน้าแรกอ่านจากที่นี่ แต่ละระบบระบุ:

- รหัสระบบและที่อยู่ตั้งต้น เช่น `transport` กับ `/transport`
- ชื่อเต็ม ชื่อสั้นสำหรับแถบระบบ ไอคอน และคำอธิบายหนึ่งบรรทัดสำหรับหน้าแรก
- เงื่อนไขการมองเห็นระบบตามบทบาท โดยใช้ `can()` จาก `src/domain/permissions.ts` ที่มีอยู่
- กลุ่มเมนูและรายการเมนู: ชื่อ ที่อยู่ ไอคอน เงื่อนไขการมองเห็น และตัวเลขจำนวนงานถ้ามี

ข้อบังคับ:

- เพิ่มระบบใหม่ต้องทำแค่สองอย่าง: เพิ่มรายการในทะเบียน และสร้างโฟลเดอร์หน้าของระบบใต้ `src/app/(app)/<รหัสระบบ>/` ห้ามต้องแก้ส่วนประกอบของโครงหน้าจอ
- โครงหน้าจอห้ามเรียกโค้ดฝั่งเซิร์ฟเวอร์ของระบบใดโดยตรง ตัวเลขจำนวนงานของระบบขนส่งมาจาก `queueCounts()` ซึ่งต้องถูกเรียกจากไฟล์ของระบบขนส่งเอง แล้วส่งให้เมนู
- การซ่อนเมนูเป็นแค่ความสะดวก ทุกหน้ายังตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ด้วยโค้ดเดิม
- เพิ่มหัวข้อ "เพิ่มระบบใหม่" ใน `README.md` อธิบายสองขั้นตอนนี้

### 3. ที่อยู่หน้า

| ที่อยู่เดิม | ที่อยู่ใหม่ |
|---|---|
| `/` (ส่งต่อไป `/jobs`) | `/` เป็นหน้าแรก |
| `/jobs` | `/transport/jobs` |
| `/jobs/new` | `/transport/jobs/new` ยังส่งต่อไปหน้ารายการพร้อม `?new=1` หรือ `?copy=` เหมือนเดิม |
| `/jobs/[id]` | `/transport/jobs/[id]` |
| `/queues/[queue]` | `/transport/queues/[queue]` |
| `/masters/transporters` | `/transport/masters/transporters` |
| `/masters/[kind]` | `/transport/masters/[kind]` |
| `/settings` ส่วนเกณฑ์ส่วนต่างน้ำหนัก | `/transport/settings` |
| `/settings` ส่วนข้อมูลบริษัท | `/admin/company` |
| `/settings/users` และ `/settings/users/[id]` | `/admin/users` และ `/admin/users/[id]` |
| `/login` และ `/api/...` | ไม่เปลี่ยน |

- ที่อยู่เดิมทุกรายการต้องส่งต่อไปที่อยู่ใหม่ พร้อมส่วนหลังเครื่องหมาย `?` ครบ เช่น `/jobs?new=1` และตัวกรองของหน้ารายการ `/settings` เดิมส่งต่อไป `/transport/settings` ใช้การส่งต่อแบบชั่วคราว
- หลังเข้าสู่ระบบไปที่ `/`
- หน้าตั้งค่าเดิมมีสองการ์ดในหน้าเดียว แยกเป็นสองหน้า แต่ละหน้าใช้ฟอร์มและคำสั่งบันทึกตัวเดิม: `ThresholdForm` กับ `saveThresholdsAction` และ `CompanyForm` กับ `saveCompanyAction`
- ข้อความที่อยู่ทุกจุดต้องตามไปที่ใหม่ ได้แก่ `href`, `action` ของฟอร์มตัวกรอง, `redirect()`, `revalidatePath()`, ชนิด `PageProps<"...">` และกฎรายการเมนูที่เปิดอยู่ ถ้า `revalidatePath()` ตกหล่น หน้าจะแสดงข้อมูลเก่าหลังบันทึก

| | รอชั่งปลายทาง + จำนวน | `/transport/queues/destination` | ทุกบทบาท |
| | ส่วนต่างรอตรวจสอบ + จำนวน | `/transport/queues/variance` | ทุกบทบาท |
| ข้อมูลหลัก | ผู้รับจ้าง รถ คนขับ | `/transport/masters/transporters` | `master.manage` |
| | ต้นทาง | `/transport/masters/origins` | `master.manage` |
| | โรงงานปลายทาง | `/transport/masters/factories` | `master.manage` |
| | ประเภทสินค้า | `/transport/masters/commodities` | `master.manage` |
| ตั้งค่าระบบนี้ | เกณฑ์ส่วนต่าง | `/transport/settings` | `settings.manage` |

**ระบบผู้ดูแลระบบ** ชื่อสั้น "ผู้ดูแล" เห็นเมื่อมี `settings.manage` หรือ `user.manage`

| รายการ | ที่อยู่ | เห็นเมื่อ |
|---|---|---|
| ผู้ใช้งาน | `/admin/users` | `user.manage` |
| ข้อมูลบริษัท | `/admin/company` | `settings.manage` |

กฎรายการเมนูที่เปิดอยู่ ให้ผลเหมือน `isActive` ใน `nav-link.tsx` ปัจจุบัน:

- "ใบงาน" เปิดอยู่เมื่ออยู่หน้ารายการใบงานหรือหน้ารายละเอียดใบงาน และไม่เปิดเมื่ออยู่ `/transport/jobs/new`
- "สร้างใบงาน" ไม่แสดงสถานะเปิดอยู่
- รายการอื่นเปิดอยู่เมื่อที่อยู่ตรงกันหรือเป็นหน้าย่อยของรายการนั้น
- ตำแหน่งหน้าในแถบบนใช้ชื่อของรายการที่เปิดอยู่ หน้ารายละเอียดใบงานจึงแสดง "จ้างรถขนส่ง › ใบงาน"

เมนูปัจจุบันซ่อน "ผู้ใช้งาน" ด้วย `settings.manage` ส่วนหน้าเองตรวจ `user.manage` ทั้งสองสิทธิ์เป็นของ ADMIN เท่านั้น การเปลี่ยนเมนูไปใช้ `user.manage` จึงไม่เปลี่ยนผลของบทบาทใด

### 5. หน้าแรก

หน้าใหม่ที่ `/` สำหรับผู้ใช้ทุกบทบาท ไม่มีการบันทึกข้อมูล

- หัวหน้า "หน้าแรก"
- การ์ดหนึ่งใบต่อระบบที่ผู้ใช้เห็นได้ อ่านจากทะเบียนระบบ: ไอคอน ชื่อเต็ม คำอธิบาย และลิงก์เปิดระบบ
- ระบบเสริมเนื้อหาในการ์ดของตัวเองได้ การ์ดระบบขนส่งแสดงจำนวนงานของคิวทั้งสามจาก `queueCounts()` เป็นลิงก์ไปคิวนั้น และลิงก์ "สร้างใบงาน" เมื่อมี `job.create`
- การ์ดผู้ดูแลระบบมีลิงก์ "ผู้ใช้งาน" และ "ข้อมูลบริษัท"

### 6. หน้าเข้าสู่ระบบและชื่อโปรแกรม

- ชื่อโปรแกรมกำหนดไว้ที่เดียว ใช้ที่หน้าเข้าสู่ระบบ ชื่อแท็บเบราว์เซอร์ และคำอธิบายของสัญลักษณ์บนแถบระบบ
- ชื่อชั่วคราวคือ "ระบบงานบริษัท" รอเจ้าของงานยืนยันชื่อจริง
- คำว่า "ระบบจ้างรถขนส่ง" เหลืออยู่เฉพาะในฐานะชื่อระบบในทะเบียนระบบ
- หน้าเข้าสู่ระบบ: การ์ดขาวกลางพื้นเทาอ่อน สัญลักษณ์โปรแกรม ชื่อโปรแกรม ฟอร์มเดิม ข้อความเดิม และ `loginAction` เดิม

### 8. ส่วนประกอบและรายละเอียดหน้าตา

- ฟอนต์คงเดิม: Leelawadee UI, Noto Sans Thai, Tahoma จากเครื่อง
- ขนาดตัวอักษร: หัวหน้า 22px ตัวหนา หัวการ์ด 15px ตัวหนา เนื้อหาและตาราง 14px ข้อความเล็กสุด 12px ตัวเลขในตารางใช้ความกว้างคงที่
- ข้อยกเว้น: หน้ารายละเอียดใบงานและหน้าต่างย่อยของหน้านั้นคงขนาดตัวอักษรใหญ่ตามเดิม (`src/components/jobs/job-type.ts` และขนาดหัวหน้ากับตัวเลขสรุปในหน้านั้น) เจ้าของงานสั่งขยายตัวอักษรหน้านี้ไว้เมื่อ 10 พฤศจิกายน ภาพต้นแบบวาดหน้านี้ด้วยตัวอักษรขนาดปกติ ซึ่งไม่ใช้ การเทียบหน้านี้กับภาพต้นแบบจึงดูเฉพาะโครงหน้าจอ สี และรูปแบบการ์ด
- คำสั่งเดิมอื่นของเจ้าของงานที่ต้องคงไว้: หน้าต่างย่อยมีขนาดคงที่ ไม่หดเมื่อพิมพ์ข้อมูล และขนาดปุ่มกับช่องกรอกไม่เล็กลง
- มุมโค้งฐาน 10px ปุ่มและช่องกรอกโค้งน้อยกว่าการ์ดเล็กน้อย
- การ์ด: ขอบ 1px และเงาบาง `0 1px 2px rgb(15 23 42 / 6%), 0 6px 16px -8px rgb(15 23 42 / 14%)` หน้าต่างย่อยและเมนูลอยมีเงาหนากว่าการ์ด
- ขนาดปุ่มและช่องกรอกคงเดิม เปลี่ยนเฉพาะสี ขอบ และมุม
- การเคลื่อนไหว: เนื้อหาหน้าเลื่อนขึ้นพร้อมจางเข้าไม่เกิน 300ms ไม่หน่วงทีละส่วน การเปลี่ยนสีเมื่อชี้ 150 ถึง 250ms เลิกการขยับเมนูไปด้านข้างเมื่อชี้ ทุกอย่างปิดเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหว
- เลิกพื้นหลังไล่สีของทั้งหน้า
- มองเห็นวงโฟกัสเมื่อใช้แป้นพิมพ์กับทุกปุ่มและลิงก์ ปุ่มที่มีแต่ไอคอนต้องมีชื่อให้โปรแกรมอ่านจอ
- ตารางกว้างเลื่อนแนวนอนภายในการ์ด ตัวหน้าไม่เลื่อนแนวนอน

ส่วนประกอบที่ต้องปรับ: โครงหน้าจอ (`app-shell.tsx`, `nav-link.tsx`, `src/app/(app)/layout.tsx`) ส่วนประกอบกลางใน `src/components/app/ui.tsx` และ `src/components/ui/` เท่าที่ต้องใช้ชุดสีใหม่ ป้ายสถานะ (`status-badges.tsx`) ตารางใบงาน (`job-table.tsx`) และทุกจุดที่ใส่สีตรง ๆ ใน `src/components/jobs/` กับหน้ารายละเอียดใบงาน

2. เทียบกับจุดย้อนกลับ: ไฟล์ในกลุ่ม "ห้ามเปลี่ยนเนื้อหา" ไม่มีความต่าง ไฟล์คำสั่งบันทึกต่างเฉพาะข้อความที่อยู่
3. ไม่เหลือสีจากชุดสีสำเร็จของ Tailwind ใน `src/` ตรวจด้วยการค้นรูปแบบ `(bg|text|border|ring)-(slate|gray|zinc|stone|red|rose|orange|amber|yellow|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|pink)-\d` ยกเว้นไฟล์ที่เจ้าของงานไม่ได้เขียนเองใน `src/generated/`
4. ที่อยู่ใหม่ทุกรายการในข้อ 3 ของการออกแบบเปิดได้ และที่อยู่เดิมทุกรายการส่งต่อถูกที่พร้อมส่วนหลัง `?`
5. เข้าสู่ระบบด้วยบทบาททั้งหก (ADMIN, TRANSPORT, WEIGHING, ACCOUNTING, APPROVER, VIEWER) แล้วเมนูที่เห็นตรงกับตารางในข้อ 4 ของการออกแบบ
6. ทดสอบการใช้งานบนฐานข้อมูลแยกด้วยบัญชี ADMIN: สร้างร่าง แก้หัวใบงาน ออกใบงาน บันทึกชั่งต้นทางและปลายทาง แนบไฟล์ ยืนยันส่วนต่าง บันทึกการเก็บเงิน คัดลอก ยกเลิก ลบร่าง เพิ่มและแก้ข้อมูลหลัก เพิ่มและแก้ผู้ใช้ บันทึกเกณฑ์ส่วนต่างและข้อมูลบริษัท หลังแต่ละครั้งหน้าจอ ตัวเลขในเมนู และหน้ารายการต้องแสดงค่าใหม่โดยไม่ต้องรีเฟรชเอง
7. เทียบหน้ารายการใบงานและหน้ารายละเอียดใบงานกับภาพต้นแบบที่ความกว้าง 375, 768, 1024 และ 1440px
8. ใช้แป้นพิมพ์อย่างเดียวไปถึงทุกรายการในแถบระบบและเมนูได้ และปิดแผงเมนูบนจอแคบด้วย Esc ได้
9. ซ้อมเพิ่มระบบ: เพิ่มระบบทดลองหนึ่งรายการในทะเบียนพร้อมหน้าเปล่าหนึ่งหน้า แล้วระบบนั้นต้องปรากฏในแถบระบบ หน้าแรก เมนู และตำแหน่งหน้า โดยไม่แก้ไฟล์โครงหน้าจอ จากนั้นลบระบบทดลองออก

## การนำขึ้นใช้งาน

เซิร์ฟเวอร์จริงรันจากผล `build` ผู้ใช้จะเห็นหน้าตาใหม่เมื่อรัน `scripts\lan\Install-TransportServer.ps1` ซ้ำด้วยสิทธิ์ผู้ดูแลเครื่อง สคริปต์หยุดเซิร์ฟเวอร์ รัน `npm install`, `db:deploy`, `db:seed` และ `build` แล้วเริ่มเซิร์ฟเวอร์ งานนี้ไม่มีการเปลี่ยนโครงสร้างฐานข้อมูล สองขั้นตอนฐานข้อมูลจึงไม่เปลี่ยนอะไร ระหว่างนั้นผู้ใช้เข้าไม่ได้ชั่วครู่ ให้เจ้าของงานเป็นคนเลือกเวลา

## ปล่อยให้ผู้ลงมือตัดสินใจ

- ชื่อไฟล์ ชื่อส่วนประกอบ ตำแหน่งและรูปแบบข้อมูลของทะเบียนระบบ
- วิธีส่งไอคอนและตัวเลขจำนวนงานจากฝั่งเซิร์ฟเวอร์ไปยังส่วนที่ทำงานในเบราว์เซอร์
- วิธีทำการส่งต่อที่อยู่เดิม และวิธีจำสถานะย่อเมนู
- ชื่อตัวแปรสี และการแปลงค่าสีเป็นรูปแบบที่ `globals.css` ใช้อยู่
- ไอคอนของแต่ละรายการ โดยคงไอคอนเดิมของเมนูเท่าที่ทำได้
- วิธีเตรียมฐานข้อมูลแยกสำหรับทดสอบ
- ลำดับงาน

## ข้อที่ผู้เขียนตัดสินใจเอง

เจ้าของงานยังไม่ได้สั่งข้อเหล่านี้โดยตรง ให้ตรวจตอนอนุมัติ

1. ย้ายหน้าขนส่งไปอยู่ใต้ `/transport` และให้ที่อยู่เดิมส่งต่อ
2. แยกหน้าตั้งค่าเป็น "เกณฑ์ส่วนต่าง" ในระบบขนส่ง กับ "ข้อมูลบริษัท" ในระบบผู้ดูแลระบบ และย้าย "ผู้ใช้งาน" ไปอยู่ระบบผู้ดูแลระบบ
3. มีหน้าแรก และหลังเข้าสู่ระบบไปหน้าแรกแทนหน้ารายการใบงาน
4. ชื่อโปรแกรมชั่วคราว "ระบบงานบริษัท"
5. ย้ายชื่อผู้ใช้และปุ่มออกจากระบบไปแถบบน
6. มีปุ่มย่อเมนูของระบบ
7. กลุ่ม "การเงิน" ในหัวตารางใบงานเปลี่ยนจากสีเหลืองอำพันเป็นสีม่วง
8. ป้าย "ยังไม่ได้รับ" ของการเก็บเงินเปลี่ยนจากสีเหลืองอำพันเป็นสีม่วง
9. กล่อง "ส่วนต่าง (%)" เป็นสีแดงพร้อมกล่อง "ส่วนต่าง" เมื่อเกินเกณฑ์ ตามภาพต้นแบบ
10. หน้ารายละเอียดใบงานคงตัวอักษรขนาดใหญ่ตามที่เจ้าของงานเคยสั่ง จึงใหญ่กว่าในภาพต้นแบบ
11. ลดการเคลื่อนไหวตอนเปิดหน้าให้สั้นลงและไม่หน่วงทีละส่วน
12. ไม่ทำโหมดมืด
